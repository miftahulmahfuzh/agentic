case "screener-no-invented-numbers":
  popupContent = `
    <h2>Ladders, Never Invented Numbers</h2>
    <p>Numbers in this tool come from exactly two places: the user types one, or the registry supplies a ladder step. Nothing else may produce one. <code>RelaxedParams</code> being non-nil <em>is</em> the relaxability gate for a condition, and every value in it must be a step on that filter's ladder — so relaxation walks a ladder it was handed rather than guessing a looser bound.</p>
    <p>The rule used to have an exception, and the exception was <strong>deleted, not deferred</strong>. PM round-two answer E1 removed the whole propose-a-threshold design on the reasoning that a proposal saves the user nothing — both paths cost two turns — while forcing the system to invent the very number the rule forbids. Gone entirely: <code>suggestions</code>, <code>expected_hits</code>, <code>pending_written</code>, <code>PendingConfirmation</code> and its session slot, <code>confirms_pending</code>, <code>explicit_relax_suggested</code>, <code>explicit_relax_confirmed</code>, and the suggest-then-confirm state machine that tied them together.</p>
    <p>Deleting it made the lock <em>stricter</em>. The system now never touches a locked condition at all — not even by proposing a value for one.</p>
    <p>What replaced it carries two facts and no proposal: the near-miss report names which condition is blocking (<code>n_dropped</code>) and the value actually <strong>reachable</strong> on that metric. Both are read off a sensitivity matrix <code>execute</code> has already paid for, so the report costs nothing extra.</p>
    <hr>
    <p><strong>Benefits:</strong></p>
    <ul>
        <li>No threshold on screen is ever a model's guess — it is the user's or the registry's.</li>
        <li>One fewer state machine, one fewer session slot, and one fewer way to drift.</li>
        <li>The near-miss report is derived from data already in hand, not from a second query.</li>
        <li>The rule is checkable: a number with no ladder step behind it is a bug, not a judgement call.</li>
    </ul>
`;
break;

case "screener-content-is-routing":
  popupContent = `
    <h2>Content Is the Routing; the Label Only Lies</h2>
    <p>The design principle, quoted from PRD section 6: <em>"Content is the routing; the label only lies."</em> When a field's content and the planner's own label disagree, the code trusts the content and logs the mismatch.</p>
    <p>It shows up first at the tool boundary. The caller must pass the user's message <strong>close to verbatim</strong> in <code>demand_description</code>, because fuzzy Indonesian terms — <code>murah</code>, <code>bagus</code>, <code>bandar</code>, <code>likuid</code> — have to survive intact for the tool's own planner to resolve them against the lexicon. A caller that helpfully normalises the sentence destroys the signal before the only component that could use it.</p>
