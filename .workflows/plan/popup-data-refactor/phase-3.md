## Goal

After this phase `hugo_docs/layouts/page/custom-home.html` contains no `switch (type)` and no popup
prose. The three feature grids and the 51 modal bodies are both generated by ranging the same
`$all` slice, built once from `hugo.Data.popups`, so a trigger and its body cannot disagree — not
because a check catches it, but because one data file emits both. A popup that names a card which
does not exist, a card with no popups, a card in no rendered section, two popups fighting over one
`order`, an empty `label` or `body`, or a body that would close its own carrier element each **fail
`~/bin/hugo` with a non-zero exit**. The file goes from 3,011 lines to 1,604.

With that substitution the patched site builds with zero WARN and zero ERROR. **This correction
has been applied to the index and to phase 2's plan by the reconciler; every plan in the set now
says `hugo.Data`.**

**F8 — the deletion range in the index and the analysis is wrong by ~18 lines.** The index says
delete `:1497`–`:2896` and the analysis puts `default:` at `:2894`–`:2896`, the `innerHTML` assign

Everything else the analysis measured holds exactly: `showPopup` at `:1490`, `closePopup` at
`:2927`, `DIAGRAM_VIEWER` at `:2941`, `openDiagramTab` at `:2943`, 51 `case "` and 51
`onclick="showPopup(` occurrences, 3,011 lines. **This plan uses the measured numbers, and the
reconciler has propagated them into the index and the analysis's Reference List.**

**F9 — Hugo decodes positive YAML integers as `uint64`, not `int`.** An order-type assertion
written as `ne (printf "%T" $p.order) "int"` fires on every single file:

```
ERROR popups/screener-lexicon.yaml: 'order' must be an integer, got uint64 (20)
...
ERROR error building site: logged 61 error(s)
```

That assertion is therefore **not** in the final plan. It is also unnecessary: the sort key is
`printf "%012d" (int $order)`, and Hugo's `int` normalises `uint64`, `int` and a quoted `"20"`
alike, while a genuinely non-numeric `order` makes `int` itself fail the build. The useful
assertion is *presence*, via `isset` — a missing `order` silently sorts the popup to the front of
its card, which is exactly the class of quiet failure R1 exists to kill.

**F10 — `errorf` does not abort the template; it accumulates.** Hugo logs every `errorf` and then
exits non-zero with `error building site: logged N error(s)`. This is better than aborting: one
build reports every broken file at once (measured: 3 simultaneous G1 errors from deleting one card
file). It also means the guard block must tolerate continuing with bad data — it does, because the
only thing downstream of a failed guard is markup nobody will ship.

**F11 — Go's escaper leaves popup ids alone inside `onclick="showPopup('…')"`.** Rendered output is
`onclick="showPopup('cache-fastlane')"`, byte-identical to today. Hyphens are not in Go's JS-string
replacement table and the ids are `[a-z0-9-]+`. No `safeJS` is needed, and none is used — the
escaper stays switched on.

**F12 — JS comments are stripped from the rendered page today, and will be after.** Hugo's
`html/template` JS-context escaper removes `//` comments. `grep -c 'Re-initialize Mermaid'` on the
*current* build returns `0`. So the comments this plan adds to `showPopup` cost nothing at render
and change no rendered byte. Pre-existing behaviour, not a change.

**F13 — no collision on `.popup-body` or `data-popup-id`.** `grep -rn 'popup-body\|data-popup-id'
layouts/ assets/ static/` returns nothing in the worktree. The names are free. `<script>` is
`display:none` by UA default and the theme adds no `script` rule, so the carriers are inert and
invisible without any CSS of their own.

## The markup contract I am implementing, and where it came from

`.workflows/plan/popup-data-refactor/phase-1.md` **did not exist** when this plan was written
(`ls` of the plan directory showed only `phase-2.md`). The contract below was therefore taken from
**`POPUP_DATA_REFACTOR_PLAN.md` decision D4 and the phase-1 description at `:213`–`:215`**, which
state it verbatim:

> the body-carrier markup `<script type="text/html" class="popup-body" data-popup-id="<id>">`, and
> the trigger markup
> `<li><button class="popup-trigger" type="button" onclick="showPopup('<id>')">LABEL</button></li>`

**Checked against phase-1.md by the reconciler: the two shapes are identical, byte for byte**, and
phase 1's `TRIGGER_RE` / `CARRIER_RE` / `H4_RE` / `TRIGGER_LINE` / `CARRIER_OPEN` (phase-1.md,
Interface Contract §3) match what Steps 2–5 below emit. Nothing to change. If a later revision of
phase 1 narrows either shape — attribute order, a `data-` attribute added, the `class` dropped —
this file's two emitting lines are the only places to touch.

**The inter-card blank line — RESOLVED, and phase 1 owns it.** Invariant I2 is stated as
"byte-identical after normalising leading indentation per line". This phase's output is *uniformly*
indented, which is R3; per-line indentation normalisation absorbs that. It does **not** absorb blank
lines, and the current page puts a blank line between feature-cards in the `agents` and `screener`
grids but **not** in the `features` grid (the column-0 authoring era, `:573`/`:585`/`:597`/`:609`
contiguous). A uniform output must pick one, and **this plan emits the blank line**, matching 7 of
the 10 cards.

Phase 1's verifier is blind to that by construction, not by tolerance (phase-1.md, Interface
Contract §3, last block): `extract_cards` is a line *classifier* — a blank line matches none of its
six patterns and is skipped without being recorded — and `compare_cards` diffs `<li>` strings it
**reconstructs** from the parsed model via `TRIGGER_LINE % (id, label)`, so whitespace between
records never reaches the diff. `norm()` is applied to bodies only, never to the trigger region.
**Neither side needs a flag and neither side changes.** Recorded in the index as decision **D6**.

> Read the property-(b) measurement at the end of this plan with that in mind: its one-line diff
> was taken over the non-blank lines of the normalised grid regions. The three added blank lines in
> the `features` grid are real, intended, and outside what I2 and `popups_verify.py` compare.

### Step 1: Insert the data index and the build-time guards

**File:** `hugo_docs/layouts/page/custom-home.html:3` — insert immediately **after** line 3
(`{{- $ogAlt := "…" -}}`) and **before** line 4 (`<!doctype html>`).

**Change:** add the 71-line block below. It opens with `{{-` and every line ends in `-}}` or an
action, so it emits nothing: `<!doctype html>` stays the first byte of the page. The variables are
declared at the template's top level, so `$all` and `$cardList` are in scope for the grids at
`:368`+ and the carriers at `:1460`+.

The guards are the heart of R1. **There is deliberately no "trigger with no body" guard.** That
state is not merely unchecked, it is unwriteable: a trigger exists because `$all` has an entry, and
that same entry emits a carrier eight hundred lines below. One data file, one slice, two render
sites. The guards cover the three ways an entry could fail to reach *one* of those sites:

| Guard | The failure it makes impossible |
|---|---|
| **G1** unknown card | the popup's card does not exist, so no grid iterates it → carrier with no trigger |
| **G2** orphan card | the card exists but nothing points at it → an empty `<ul>` ships |
| **G4** unknown section | the card exists and has popups, but no grid filters for its section → every one of its carriers has no trigger |
| **G3** order collision | both render, but in an order nobody chose |

G1 and G4 are the two halves of "a body with no trigger"; together with structural impossibility on
the other side, the trigger ⇔ body correspondence is total.

**Code:**

```go-html-template
{{- /* ---------------------------------------------------------------------
     POPUP DATA - index, build-time integrity guards, and render order.

     Source of truth: hugo_docs/data/popup_cards/*.yaml (10) and
     hugo_docs/data/popups/*.yaml (51). ONE popup file carries both the
     trigger button's `label` and the modal's `body`, and the three feature
     grids and the carrier block below both iterate $all - so "a trigger with
     no body" is not a bug that gets caught, it is a state that cannot be
     written down. That is R1.

     Everything here runs once, before a byte renders. Every violation is an
     errorf, and errorf fails `hugo` with a non-zero exit:
       G1  a popup names a card that does not exist
       G2  a card has no popups pointing at it
       G3  two popups in one card share an `order`
       G4  a card's `section` is not one of the three rendered sections - such
           a card renders nowhere while its popups still emit bodies, which is
           the mirror image of G1 and the same failure
     plus per-field assertions: heading / icon / order / label / body present
     and non-empty, and no body carrying a literal script-closing tag, which
     would terminate its carrier element early.

     `hugo.Data`, not `.Site.Data`: the latter is deprecated as of Hugo
     v0.156.0 and logs a WARN, which invariant I3 forbids.
   */ -}}
{{- $cards := hugo.Data.popup_cards -}}
{{- $popups := hugo.Data.popups -}}
{{- if not $cards }}{{ errorf "popup data: hugo_docs/data/popup_cards/ is missing or empty" }}{{ end -}}
{{- if not $popups }}{{ errorf "popup data: hugo_docs/data/popups/ is missing or empty" }}{{ end -}}
{{- $sections := slice "agents" "screener" "features" -}}
{{- $cardList := slice -}}
{{- range $cid, $c := $cards -}}
  {{- if not ($c.heading | default "") }}{{ errorf "popup_cards/%s.yaml: missing or empty 'heading'" $cid }}{{ end -}}
  {{- if not ($c.icon | default "") }}{{ errorf "popup_cards/%s.yaml: missing or empty 'icon'" $cid }}{{ end -}}
  {{- if not (isset $c "order") }}{{ errorf "popup_cards/%s.yaml: missing 'order' - the card would silently sort to the front of its section" $cid }}{{ end -}}
  {{- if not (in $sections ($c.section | default "")) }}{{ errorf "G4 unknown section: popup_cards/%s.yaml has section %q, expected one of %v. A card in no section renders nowhere while its popups still emit bodies - a body with no trigger." $cid ($c.section | default "") $sections }}{{ end -}}
  {{- $cardList = $cardList | append (dict
        "id"      $cid
        "section" ($c.section | default "")
        "heading" ($c.heading | default "")
        "icon"    ($c.icon | default "")
        "sortkey" (printf "%012d|%s" (int ($c.order | default 0)) $cid)) -}}
{{- end -}}
{{- $cardList = sort $cardList "sortkey" -}}
{{- $all := slice -}}
{{- range $id, $p := $popups -}}
  {{- $card := $p.card | default "" -}}
  {{- if not $card }}{{ errorf "G1 unknown card: popups/%s.yaml has no 'card' field" $id }}
  {{- else if not (index $cards $card) }}{{ errorf "G1 unknown card: popups/%s.yaml names card %q, but hugo_docs/data/popup_cards/%s.yaml does not exist" $id $card $card }}{{ end -}}
  {{- if not (isset $p "order") }}{{ errorf "popups/%s.yaml: missing 'order' - the popup would silently sort to the front of card %q" $id $card }}{{ end -}}
  {{- if not ($p.label | default "") }}{{ errorf "popups/%s.yaml: missing or empty 'label' - the trigger button would render blank" $id }}{{ end -}}
  {{- if not ($p.body | default "") }}{{ errorf "popups/%s.yaml: missing or empty 'body' - the modal would open empty" $id }}{{ end -}}
  {{- if strings.Contains ($p.body | default "") "</script>" }}{{ errorf "popups/%s.yaml: 'body' contains </script>, which would terminate its carrier element early and corrupt the page" $id }}{{ end -}}
  {{- $all = $all | append (dict
        "id"      $id
        "card"    $card
        "order"   ($p.order | default 0)
        "label"   ($p.label | default "")
        "body"    ($p.body | default "")
        "sortkey" (printf "%012d|%s" (int ($p.order | default 0)) $id)) -}}
{{- end -}}
{{- range $cid, $c := $cards -}}
  {{- $members := where $all "card" $cid -}}
  {{- if eq (len $members) 0 }}{{ errorf "G2 orphan card: popup_cards/%s.yaml has no popups - no hugo_docs/data/popups/*.yaml sets card: %s, so the card would render an empty list" $cid $cid }}{{ end -}}
  {{- $seen := dict -}}
  {{- range $m := $members -}}
    {{- $k := printf "%v" $m.order -}}
    {{- if index $seen $k }}{{ errorf "G3 order collision: popups/%s.yaml and popups/%s.yaml are both in card %q with order: %v - render order would fall back to the id tie-break instead of the author's intent" $m.id (index $seen $k) $cid $m.order }}{{ end -}}
    {{- $seen = merge $seen (dict $k $m.id) -}}
  {{- end -}}
{{- end -}}
```

Notes on the mechanics, each of them load-bearing and each verified in the prototype:

- **`sortkey`, not a two-key sort.** Hugo's `sort` takes one key. `printf "%012d|%s"` over
  `(order, id)` makes `(order, id)` a single lexicographic string, so ordering is deterministic
  without relying on the sort being stable. `int` absorbs the `uint64` of F9 and a quoted `"20"`
  alike.
- **`isset`, not a type check.** See F9. A present-but-weird `order` still sorts correctly; an
  absent one does not, and that is what is asserted.
- **`$seen = merge $seen (dict …)`** — assignment (`=`, not `:=`) to a variable declared outside the
  inner `range`. Go templates have supported this since Go 1.11; it is how G3 accumulates.
- **`strings.Contains`** is the namespaced form; `in` would also work but reads as a set test.
- The `</script>` inside the G-assertion is inside a template *action*, not template text, so
  Hugo's HTML lexer never sees it as a tag. Verified: the assertion fires correctly on a body that
  actually contains one, and the page is otherwise unaffected.

**Impact:** no rendered bytes. The page's first output byte is still `<!doctype html>`. The build
now fails on bad popup data.

### Step 5: Emit the 51 body carriers

**File:** `hugo_docs/layouts/page/custom-home.html:1460` — insert immediately **after** line 1460

**Change:** add the block below. Placement is the inert spot directly beneath the modal the


Why each part is what it is:

- **`sort $all "id"`, not `range hugo.Data.popups`.** Same slice the grids iterate, so the

  a stable, reviewable diff.
- **`| safeHTML` is not optional.** Without it the body comes back fully entity-escaped

- **Not `jsonify`, not `<template>`.** Decision D4 rejected both: `jsonify` re-encodes `<` and puts

### Step 6: Rewrite `showPopup`, delete the switch

**File:** `hugo_docs/layouts/page/custom-home.html:1490`–`:2925` — replace all 1,436 lines, from
`      function showPopup(type) {` through the `      }` that closes it. That range contains, and
therefore deletes:

| What | Lines |
|---|---|
| `let popupContent = "";` | `:1495` |
| `switch (type) {` … 51 `case` bodies … `}` | `:1497`–`:2914` |

`:2926` (blank) and `:2927` (`function closePopup() {`) are **not** in the range and are not
touched. Neither is anything above `:1490`.

**Change:** `showPopup` becomes a lookup.

**Code:**

```javascript
      // Popup bodies live in the <script type="text/html" class="popup-body">
      // carriers above, one per hugo_docs/data/popups/<id>.yaml. Script
      // elements are raw text, so textContent is the authored HTML
      // byte-for-byte with entities undecoded — exactly what innerHTML wants.
      function showPopup(type) {
        lastTrigger = document.activeElement;
        const modal = document.getElementById("popup-modal");
        const content = document.getElementById("popup-content");
        const carrier = document.querySelector(
          '.popup-body[data-popup-id="' + type + '"]'
        );

        if (!carrier) {
          // Unreachable by construction: the button and its body are emitted
          // from one data file in one loop, and the build fails on a popup
          // whose card is unknown (G1) or a card that renders nowhere (G4).
          // If it happens anyway, fail loudly and do not open — an empty
          // modal reading "Feature details not available." is a shippable
          // failure, which is the thing this refactor exists to delete.
          console.error("showPopup: no popup body for id " + JSON.stringify(type));
          return;
        }

        content.innerHTML = carrier.textContent;
        modal.style.display = "block";

        // Re-initialize Mermaid for new content
        if (content.querySelector(".mermaid")) {
          setTimeout(() => {
            mermaid.init();
          }, 100);
        }
      }
```

Four things held fixed on purpose:

1. **`lastTrigger = document.activeElement;` stays verbatim as the first statement.** `closePopup`
   at `:2927` reads it to restore focus; moving or conditioning it would silently break keyboard
   navigation. Setting it before the early return is harmless: the modal never opens, so
   `closePopup` is never called, and the next successful `showPopup` overwrites it.
2. **The Mermaid re-init block is copied verbatim**, comment included. 13 of the 51 bodies carry a
   `<div class="mermaid">` and render nothing without it. Its logic is unchanged.
3. **The selector mirrors `openDiagramTab` at `:2944`** — `'[data-diagram-id="' + id + '"]'` — so
   the file keeps one idiom for "find the inert carrier for this id", rather than growing a second.
4. **`textContent`, not `innerHTML`, on the read side.** Script elements are raw text; `textContent`
   returns the authored bytes with entities *undecoded*, which is what `#popup-content.innerHTML`
   must receive for invariant I1 to hold by construction.

**What replaces `default:`, and why.** The old fallback opened the modal and wrote
*"Feature details not available."* — a failure that renders, ships, and looks deliberate. The user's
specification names it directly: *"a popup-trigger whose string has no matching case renders an
EMPTY MODAL with no build error — a failure the page can ship."* Deleting the switch without
deleting that behaviour would carry the bug across the refactor.

The replacement **refuses to open the modal and logs `console.error`**. The reasoning:

- After this phase a missing id is *unreachable from the page itself*. Every `onclick` is generated
  from an `$all` entry, and every `$all` entry emits a carrier. G1 and G4 make the two ways that
  correspondence could break into build failures. The only remaining caller of `showPopup('x')` with
  an unknown `x` is a human typing it into a console or a future hand-written call site.
- For that caller, a silent empty modal is the worst answer and an exception is the second worst
  (it would leave the page's focus state half-changed). `console.error` plus a no-op is diagnostic
  where a developer is already looking, and invisible where a reader is.
- Not opening is the honest signal. The modal staying shut, with the trigger still focused, is
  indistinguishable from "that button did nothing" — which is true — rather than from "this feature
  has no documentation", which was a lie.

**Impact:** −1,404 lines. `grep -c 'case "' custom-home.html` goes to 0. The file becomes editable
by HTML tooling because the HTML is now in HTML files.
